# Hisab (com.selfkit.hisab)

Status: **v0.1.1, usable on Linux and Android.** (0.1.1 = QA fixes, see [QA 2026-11-15](#qa-2026-11-15).) Money app: accounts, expenses/income/transfers, categories with budgets, splits, photos, currencies, loans with repayments and reminders, recurring items and subscriptions, savings goals, search and filters, CSV import (Hisab export or bank CSV) and CSV/PDF export, desktop quick-capture popup, Android home-screen widget.

Design (approved 2026-11-15 from mockups): warm neutral greys (#f3f3f1 / #0e0e0d), one green accent (#2e7a4d light, #5dbb7e dark) matching the icon, red only for overdue / over budget / destructive. Soft cards, rounded number-pad keys, hand-made SVG charts, Inter with tabular numbers. Light/dark follow the system unless set in Settings.

Feature notes: [categories.md](categories.md) · [loans.md](loans.md) · [currencies.md](currencies.md) · [csv-import.md](csv-import.md) · ([sms-import.md](sms-import.md): removed 2026-11-15)

## Screens
- **Home = add expense** (phone): top bar (History, Insights, Accounts, More), month summary card (spent, budget bar with an even-pace mark, remaining — only spending in categories with a budget counts against it, L2-12 — balance), the 3 last-entered entries, then the fixed input panel: Expense / Income / Transfer, big amount with currency and account chips (Transfer adds a "to" chip), sliding category row with edge fade and "+ New", note (words with `#` become tags, Bangla included — L12), date, photo, Split, number pad (hold ⌫ to clear) and Save. Saving shows "Saved · $12 · Food  Undo" ("Food + Bills" for a split — L2-9). The draft is saved on every key (localStorage at once, SQLite after a short pause), so Back, a crash or a restart never loses what was typed, and typing never waits for the database. Save first sends a draft write still waiting for its pause, so it can't land after the cleared draft (C10). Overview, Insights and History keep only the newest reply when several requests overlap (the commands run in parallel — C7).

## Data model (selfkit-core records in `hisab.db`)
Amounts are decimal numbers rounded to 2 places, in the record's `currency` (ISO code). Dates are local `YYYY-MM-DD`, times `HH:MM`; `created_at` is UTC ms. Every record also has core's `updated_at` (UTC ms) + `tz_offset`.
- `accounts`: `name, kind (cash|bank|wallet|card|other), currency, explicit_currency (bool: the user picked this currency in the account sheet or chose "Keep"; missing on older accounts = chosen unless USD/the main currency of the time), opening, archived, order`.
- `categories`: `name, kind (expense|income), icon, color, budget (monthly, main currency, 0 = none), archived, order`. Delete = `archived: true`. A fresh install seeds Cash (`acct-cash`) and the default categories (`cat-exp-food`, `cat-inc-salary`, …) with fixed ids, so a second device doesn't add duplicates when sync is turned on (C19).
- `transactions`: `kind (expense|income|transfer), amount, currency, date, time, account, category, splits [{category, amount}] (≥ 2 parts that add up to amount; category = first part), tags [], note, photos [photo ids], source (manual|sms|recurring|import; `sms` only on old entries), recurring (id; generated entries have the id `rec-<recurring id>-<date>`, the same on every device — C18), import_batch (CSV imports), created_at`. Transfers: `to_account, to_amount` (in the destination account's currency; converted when not typed); category empty.
- `recurring`: `name, freq (daily|weekly|monthly|yearly), interval, start, next, end, active, subscription, template {kind, amount, currency, account, category, note, tags}`.
- `loans`: `direction (lent|borrowed), person, title, description, amount, currency, given, due, account (optional, moves its balance), photos [], repayments [{id, date, amount, note}], remind, remind_days, remind_time`.
- `goals`: `name, target, currency, deadline, contributions [{id, date, amount (negative = taken out), note}], archived`.
- `sms`: legacy collection from the removed SMS import (kept so synced old records stay valid; nothing writes it any more).
- `rates` (single record id `hisab-rates`): `base, rates {CUR: units per 1 base}, manual {CUR: …}, fetched_at`.
- Prefs (kv `hisab.prefs`, not synced): `theme, rank (manual|used), account, notify` (old `sms, sms_since` are ignored).
- Last known main currency (kv `hisab.main`, not synced): fallback when the shared settings can't be read.
- Add-screen draft (kv `hisab.draft`, not synced): the half-typed entry. Every change goes to localStorage (`hisab.draft`) at once; SQLite gets it after 0.3 s without typing (localStorage alone is not durable when the app is killed) and immediately when the app goes to the background (writes chained in order; Save waits for them). Both copies carry `_t` (ms) and boot takes the newer. Data commands run with `#[tauri::command(async)]` so a busy database (sync pass) never blocks the UI thread (0.1.5 fix for typing stalls in 0.1.4). `save` takes an optional `draft` and writes it in the same call (the cleared draft after Save). Draft `date` "" = today at the moment of saving; draft `currency` "" = the account's entry currency (main unless chosen); an untouched draft (no amount) drops a hand-picked currency, so a restart lands on main.
- Computed (never stored): account `balance, balance_main, entry_currency` (new entries' default: the account's currency only if explicit, else main); snapshot `stale_accounts` (relabel offer); category `usage, spent`; loan `repaid, remaining, remaining_main, status, days_left`; goal `saved`; recurring `monthly`; tx `amount_main`.
- Reading from other apps (Reflect): open `hisab.db` read-only; spending per day = sum of `transactions` with `kind = expense` converted with `rates`.

## Photos
Added from the add screen, the edit sheet and loan proof. On Android "Add photo" first asks **Take photo** (system camera; the photo stays private in Hisab, never in the phone gallery; the temporary capture is deleted after import) or **Choose from gallery** (system picker), Back/Cancel closes the sheet; desktop opens the file picker directly ([../../components/photo-source.md](../../components/photo-source.md), since 0.1.2; `lib/photo.ts` `pickImage`, `SelfkitPhotos.kt`, `<queries>` IMAGE_CAPTURE in the manifest — without it Android 11+ silently fell back to the gallery). The full-screen viewer has **Save to gallery** (Android `Pictures/Selfkit/Hisab`; desktop **Save to Pictures** → `~/Pictures/Selfkit/Hisab`, command `photo_export`). Picked in the webview (`<input type=file>`), shrunk to ≤ 2400 px on the long edge and encoded as WebP quality 0.9 by canvas (document quality). Stored as files in `<data_dir>/hisab-photos/<uuid>.webp` (JPEG only if the webview can't encode WebP; WebKitGTK and Android WebView both can). Records keep the photo id. Not yet uploaded to S3: when core gets a local blob index, these files go through `sync::s3::BlobStore` (encrypted).

## Reminders
Loan reminders are off until turned on (Settings, or automatically the first time you save a loan with a reminder, which also asks Android for notification permission). If Android refuses notifications, the save toast and Settings say reminders won't show (P11). Fire `remind_days` before `due` at `remind_time` local. Android: exact alarms via `tauri-plugin-notification` (manifest USE_EXACT_ALARM), rescheduled on every change and at startup (small icon: the monochrome `ic_stat_hisab` drawable, set per notification with the builder's `.icon()`). Desktop: 20 s timer while the app runs.

## Main currency fix 2026-11-15
Bug: "BDT goes back to USD after adding an entry or a restart". Cause: the first start seeds "Cash" in the shared default USD; the add screen follows the account's currency, so after every Save (draft currency reset) and restart it showed USD again, and those entries were stored in USD. On desktop, Agenda/Dusk also saved their whole startup copy of the shared settings, which could write USD back over BDT. Fix: `currency.rs` (read only `main_currency`, keep the last known value; changing it moves unused default accounts along, converts category budgets, offers used accounts in the old/default currency for a relabel), core `Settings::update` used by every app, UI listens to `settings-changed` and has no USD fallback. Details: [currencies.md](currencies.md). Tests: `currency::tests` (5) + core `update_keeps_other_apps_changes`.

## App lock
Optional PIN/passphrase (+ fingerprint on Android, + "Hide content in app switcher") from Settings → App lock; locks on start and after Immediately / 1 / 5 / 15 min away. Shared implementation: [../../components/app-lock.md](../../components/app-lock.md). Hooks here: `<LockGate appName="Hisab">` in `src/App.svelte`, `<LockSettings>` in `src/components/Settings.svelte` (under Sync), `LockHandle::new("hisab", …)` + `lock_*` commands in `src-tauri/src/lib.rs`, "---- Selfkit lock" blocks in `MainActivity.kt` + `SelfkitLock.kt`, `.skl` tokens in `src/app.css`, feature `lock-test` in `src-tauri/Cargo.toml`. The quick-add popup is not gated.
