# Hisab · currencies

- Main currency = shared Selfkit setting `main_currency`, changeable in Settings. It is the default everywhere: totals, budgets, charts, exports, new transactions (when the account doesn't say otherwise), new accounts, loans, goals, recurring items, SMS imports without a currency. Another currency appears only where the user chose one for that item (an account made in EUR, a transaction set to another currency). USD is only the shared first-start default when nothing was ever chosen.
- Reading it (`currency::read_main`): only the `main_currency` field of the shared record is read, so a record core can't fully parse no longer reads as USD; if it can't be read at all, the last known value (kv `hisab.main` in Rust, localStorage `hisab.main` in the UI) is kept.
- Changing it (`main_currency_set` → `currency::set_main`): changes only that field via core `Settings::update` (other apps' fields kept). Accounts still in the old main currency that have **no entries and no opening balance** (e.g. the "Cash" account made at first start) switch to the new main currency automatically. Accounts in the old currency that **are** used are listed in Settings with "Switch to BDT / Keep USD": Switch (`account_relabel`) relabels the account and its entries that were in the old currency (numbers unchanged, not converted). Nothing used is changed without asking. Category budgets (stored in the main currency) are converted with the saved rates on a real change (kept as they are if a rate is missing). Picking the currency that is already the main one (e.g. BDT was set before this fix but "Cash" had been seeded in USD) offers every account still in the shared first-start default (USD), and switches nothing by itself.
- Shortcut saves (`settings_set`) change only `shortcuts.add_expense` and never the main currency (a stale copy in the UI used to be able to write it back).
- Bug fixed 2026-11-15 ("BDT goes back to USD"): the first start seeded "Cash" in USD, the add screen follows the account's currency, and after every save/restart the draft currency reset to the account's USD. Also on desktop, Agenda/Dusk saved their whole startup copy of the shared settings (overwriting BDT with USD); all apps now use `Settings::update`.
- Every account, transaction, loan and goal has its own currency. Transfers between accounts in different currencies store the arriving amount (`to_amount`); if not typed it is converted.
- Rates come from open.er-api.com (free, no key) when online and older than 12 h, or with "Update now"; they are cached in the synced `rates` record, so everything works offline. Typing a rate in Settings ("1 USD = 120 BDT") stores a hand override (`manual`) that wins over fetched rates; clearing it goes back to the fetched one.
- A currency without any rate counts 1:1 and Insights shows a warning naming it.
- Code: `src-tauri/src/currency.rs`, `src-tauri/src/fx.rs`, `src/lib/rates.ts`, `components/Settings.svelte`, `CurrencySheet.svelte`.
