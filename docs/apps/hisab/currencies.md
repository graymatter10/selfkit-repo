# Hisab · currencies

- Main currency = shared Selfkit setting `main_currency`, changeable in Settings. It is the default everywhere: totals, budgets, charts, exports, new transactions, new accounts, loans, goals, recurring items, CSV imports without a currency column. Rule (user): "set global is used everywhere by default unless explicitly told to use another one".
- **Explicit account currency** (`accounts.explicit_currency`): set when the user picks a currency in the account sheet (or taps "Keep USD" on the offer). Only then do new entries on that account start in the account's currency; otherwise they start in the main currency (`currency::entry_currency`, shown to the UI as `entry_currency` on each account). Older accounts without the flag count as chosen unless their currency is the first-start USD or the main currency of the time. The seeded "Cash" has `explicit_currency: false`. Entries in another currency than their account still convert for the account balance with the saved rates.
- **Add-screen draft**: `currency` "" = the account's entry currency. A currency picked by hand lasts for that one entry: Save resets it, and an untouched draft (no amount) drops it on restart. Another currency appears only where the user chose one for that item (an account made in EUR, a transaction set to another currency). USD is only the shared first-start default when nothing was ever chosen.
- Reading it (`currency::read_main`): only the `main_currency` field of the shared record is read, so a record core can't fully parse no longer reads as USD; if it can't be read at all, the last known value (kv `hisab.main` in Rust, localStorage `hisab.main` in the UI) is kept.
- Changing it (`main_currency_set` → `currency::set_main`): changes only that field via core `Settings::update` (other apps' fields kept). Accounts whose currency was never chosen (first-start USD or the old main) follow: with **no entries and no opening balance** they switch automatically; **used** ones are offered. Category budgets (stored in the main currency) are converted with the saved rates on a real change (kept as they are if a rate is missing).
- **The offer** (`snapshot.stale_accounts` → `StaleOffer.svelte`): used, non-archived accounts in another currency than main that were never chosen. Shown in Settings → Currencies until answered (no need to re-pick the main currency: on the phone, main was already BDT and re-picking showed nothing), and once as a dismissible banner on Home and Accounts (× hides it per account + main currency, localStorage `hisab.staleSeen`). **Switch to BDT** (`account_relabel`) relabels the account and its entries in the old currency (numbers unchanged, not converted). **Keep USD** (`account_keep_currency`) sets `explicit_currency`. At startup (`boot` → `currency::follow_main`) unused never-chosen accounts follow main.
- Shortcut saves (`settings_set`) change only `shortcuts.add_expense` and never the main currency (a stale copy in the UI used to be able to write it back).
- Bug fixed 2026-11-15 ("BDT goes back to USD"): the first start seeded "Cash" in USD, the add screen follows the account's currency, and after every save/restart the draft currency reset to the account's USD. Also on desktop, Agenda/Dusk saved their whole startup copy of the shared settings (overwriting BDT with USD); all apps now use `Settings::update`.
- Every account, transaction, loan and goal has its own currency. Transfers between accounts in different currencies store the arriving amount (`to_amount`); if not typed it is converted.
- Rates come from open.er-api.com (free, no key) when online and older than 12 h, or with "Update now"; they are cached in the synced `rates` record, so everything works offline. Typing a rate in Settings ("1 USD = 120 BDT") stores a hand override (`manual`) that wins over fetched rates; clearing it goes back to the fetched one.
- A currency without any rate counts 1:1 and Insights shows a warning naming it.
- Bug fixed 2026-11-15 (round 2, phones): "$ 0 / USD" on the add screen with main BDT, snapping back to USD after each save, and no visible relabel offer — fixed by the explicit-currency rule and the snapshot-driven offer above. Tests: `currency::tests`.
