# Daily notes with photos

For any day: a short text (≤ 1000 characters) and any number of photos. Shown on Today and on past days.

- **Empty state:** a row "Add a note about today" (or "about this day"). Filled: text (3 lines on phone, tap to edit) + square thumbnails; tapping a thumbnail opens it full size (Back/Escape/tap closes).
- **Editor:** full screen on phone (✕, date, Save; "Delete note" at the bottom), a dialog on desktop (Cancel / Save, Ctrl+Enter saves, Escape closes). Back on Android saves unsaved changes instead of asking. Deleting shows "Note deleted · Undo".
- **Photos:** "Add photo" on Android opens the shared sheet **Take photo** (system camera, kept private in Chrono, not in the gallery; temp capture deleted after import) / **Choose from gallery** / Cancel (Back closes it); desktop opens the file picker directly ([../../components/photo-source.md](../../components/photo-source.md), since 0.1.1). Picked photos are scaled in the webview to document quality (longest side ≤ 2400 px, WebP at q 0.85, JPEG where the webview cannot encode WebP), sent to Rust as base64 and stored as a file in `<data_dir>/chrono-photos/` with a `photos` record (`file, mime, w, h, bytes, sha256, created_at`). Removing a photo from a note keeps the file (undo-safe); orphan clean-up is a later step. The full-screen viewer has **Save to gallery** (Android `Pictures/Selfkit/Chrono`; desktop **Save to Pictures** → `~/Pictures/Selfkit/Chrono`, command `photo_export`).
- **Data:** `day_notes` record id `n-<YYYY-MM-DD>` `{day, text, photos: [ids], updated_at}`; saving empty text with no photos deletes it.
- **Code:** `src-tauri/src/notes.rs`, commands `note_get`, `note_save`, `photo_save`, `photo_get`, `photo_export`; UI `components/NoteCard.svelte`, `NoteEditor.svelte` (gallery + camera hidden inputs, `askPhotoSource`), `Photo.svelte`, `PhotoViewer.svelte`, `lib/photos.ts`, `lib/photo-source.ts`; Android `SelfkitPhotos.kt` + `<queries>` IMAGE_CAPTURE in the manifest (without it Android 11+ silently fell back to the gallery).
- **Not yet:** photo bytes are not uploaded to S3 (records sync, files stay on the device that added them), like Agenda.
